# Pinecrest Health — Reducing 30-day Readmissions with Care-Coordinator Outreach

**Industry:** Healthcare providers (hospital systems)
**Customer problem:** Pinecrest Health (a fictional 3-hospital system) has a **14.7% 30-day readmission
rate**. Every readmission is a CMS Hospital Readmissions Reduction Program penalty risk and an avoidable
cost. Care coordinators have time to call only a fraction of discharged patients, so today they work
the list alphabetically. They need to know **who is most likely to bounce back, why, and what to do
first** — and to record what they did.

**Solution:** one integrated data journey on Databricks, from raw discharge files to an app the care
team uses every morning.

> All data is **synthetic**, generated by `data_gen/generate.py` (fixed seed). No real patients,
> customers or PHI.

## Architecture

```

 (UC volume pinecrest_raw)                  ─ tags (phi), column masks, comments, lineage ─
        │                                                          │
        ▼   ① Lakeflow Declarative Pipeline (serverless)           │
   pc_bronze_*  ──expectations──▶  pc_silver_*  ──▶  pc_gold_discharge_features
                                                      pc_gold_facility_readmissions
                                                              │
                                   ③ ML: GBM model (MLflow, UC registry, alias champion)
                                                              ▼
                                                  pc_gold_readmission_risk ──────▶ ⑤ Genie space
                                                              │  (synced table)       "Pinecrest Readmission Insights"
                                                              ▼
                       ④ Lakebase (Postgres) pinecrest-lakebase
                          public.pc_risk_worklist, public.pc_care_notes  (read-only, synced)
                          pinecrest.care_actions                          (writable)
                                                              │
                                                              ▼
                       ⑥ Databricks App  pinecrest-care-coordinator (Streamlit)
                          ranked worklist · "Explain risk with AI" (Claude via serving endpoint)
                          · Approve action → writes pinecrest.care_actions
```

## How the stages connect (not siloed)

One patient, end to end — `PC-01684`:

1. Discharged from Pinecrest Main (CHF, to skilled nursing, no follow-up booked) → raw file → bronze → silver → gold (**Lakeflow**).
2. Its name and phone are tagged `phi` and masked for anyone outside the care team (**Unity Catalog**).
3. The model scores it **0.91 → High**, action *"Schedule follow-up visit within 7 days"* (**ML**).
4. Genie lists it first for *"Which high-risk patients have no follow-up visit scheduled?"* (**Genie**).
5. The score is synced to Lakebase and served to the app in milliseconds (**Lakebase**).
6. A coordinator opens it in the app, gets an AI explanation, approves the action, and it is written to `pinecrest.care_actions` (**App**).

## Reproduce

```bash
python3 data_gen/generate.py                         # synthetic raw files
# upload data_gen/raw/* to /Volumes/users/narasimha_kamathardi/pinecrest_raw/{patients,encounters,care_notes}/
# create + run the Lakeflow pipeline from 01_lakeflow/pipeline.sql (serverless)
# run 03_ml/train_readmission_model.py on serverless
python3 scripts/sql_evidence.py evidence/02_unity_catalog_governance.md 02_unity_catalog/governance.sql
bash 04_lakebase/synced_tables.sh                    # Lakebase instance, UC database catalog, synced tables
# run 04_lakebase/setup_lakebase.py on serverless
python3 05_genie/ask_genie.py > evidence/05_genie_conversations.md
databricks apps deploy pinecrest-care-coordinator --source-code-path <workspace>/06_app
```

Note: `04_lakebase/setup_lakebase.py` contains a one-line repair `UPDATE` (a no-op on re-run). An earlier
version of the notebook ran a write test against a synced table as its owner; the repair restores that row
so Postgres matches Unity Catalog, and the app itself is granted `SELECT` only on synced tables.

`scripts/` holds the helpers that turn each run into committed text evidence
(`sql_evidence.py` for SQL, `export_run_output.py` for notebook job runs).
